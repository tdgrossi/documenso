## Root Cause

**Root cause identified:** The imports of `DocumentDistributionMethod` and other enums use `@prisma/client` which does NOT export these enums. The enums are actually generated by `zod-prisma-types` into `@documenso/prisma/generated/types.ts`.

**Evidence:**
- `DocumentDistributionMethod` is NOT available on `@prisma/client` — confirmed via node REPL: `Prisma.DocumentDistributionMethod` is `undefined`
- `DocumentDistributionMethod` IS exported from `@documenso/prisma/generated/types.ts` (generated by `zod-prisma-types`)
- Only ONE file correctly imports from `@documenso/prisma/generated/types` (`configure-document-view.types.ts`)
- ALL OTHER files (10+ files) incorrectly import from `@prisma/client`

**Files with wrong imports:**
- `packages/lib/types/document-email.ts` — imports from `@prisma/client` (WRONG)
- `packages/lib/types/document-meta.ts` — imports from `@prisma/client` (WRONG)
- `packages/lib/constants/document.ts` — imports from `@prisma/client` (WRONG)
- `packages/lib/utils/document.ts` — imports from `@prisma/client` (WRONG)
- `packages/lib/client-only/recipient-type.ts` — imports from `@prisma/client` (WRONG)
- `packages/lib/server-only/document-meta/upsert-document-meta.ts` — imports from `@prisma/client` (WRONG)
- `packages/lib/server-only/recipient/update-recipient-next-reminder.ts` — imports from `@prisma/client` (WRONG)
- `packages/lib/server-only/template/create-document-from-template.ts` — imports from `@prisma/client` (WRONG)
- `packages/app-tests/e2e/envelope-editor-v2/envelope-settings.spec.ts` — imports from `@prisma/client` (WRONG)
- `packages/ui/primitives/document-flow/add-subject.types.ts` — imports from `@prisma/client` (WRONG)

**Correct import (already used in 1 file):**
- `import { DocumentDistributionMethod } from '@documenso/prisma/generated/types';` (used in `configure-document-view.types.ts`)

**Why it worked before:** Likely the Vite config's `ssr.external: ['@prisma/client']` caused Vite to treat it as a CommonJS module that gets `require()`d at runtime. CommonJS doesn't have the ESM "named export" concept — `import { X }` from CJS returns the module.exports object, which doesn't have `X` as a direct property.

**Fix:** Change all incorrect `@prisma/client` enum imports to `@documenso/prisma/generated/types`._

## Fix

**Approach:** Replace all incorrect `@prisma/client` enum imports with `@documenso/prisma/generated/types`.

**Files to change (10 files):**


**Note:** The Vite SSR `external: ['@prisma/client']` config is correct — it's proper to keep `@prisma/client` external since the actual PrismaClient is used server-side. The issue is the wrong import path for the enum types._
